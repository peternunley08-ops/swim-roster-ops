How people sign in

Real accounts, real security. Who you are decides what you can do — enforced by the database, not just the screen.

Open the app
Installable web app (add to home screen). Loads instantly, works offline once cached.
→
Sign in
Email + password via Supabase Auth. No public sign-ups — only an owner creates accounts.
→
Role check
Your profile says owner or instructor. Row-Level Security enforces it server-side.
→
What you can do
Owner edit everything, manage staff & accounts.

Instructor view rosters, take attendance, request trades.
Account creation is owner-only and server-side. Adding/deleting an account runs through a secured Supabase Edge Function (bright-api) using a service key the browser never sees. Public sign-up stays OFF, so no stranger can register and read student info.

The data — one source of truth

Everything lives in one owner-owned record (the "roster blob"), plus a small per-instructor record for their own marks.

◆ Roster blob  — owner writes
weeks — per week: the roster (students: name, level, time, guardian, age, balance), instructor assignments, and attendance.
freeSwim — lifeguard pool, who's on duty, stations & the rotation (auto or manual placement).
staff — each person's role (instructor / lifeguard / both), extra non-login people, and daily who's-here.
accounts — the logins + their display names.
switchRequests — trade / pick-up / drop requests awaiting owner approval.
◆ Instructor record  — each instructor writes only their own
attendance — the present/absent marks that instructor took.
requests — the trades / pick-ups / drops they submitted.
RLS makes this physically impossible to forge — an instructor can't write the roster blob or anyone else's record.
name links by spelling no schema changes needed offline cache + retry

The shared name layer  new

One unified list of people that every screen reads from — so names finally flow consistently everywhere.

One people list
Accounts + lifeguards + lesson instructors + added staff, merged & de-duplicated into a single roster of people, each with a role.
Roles drive coverage
Tag someone lifeguard or both → they automatically appear in the free-swim "on duty today" list. No double entry.
Rename once, everywhere
Renaming a person updates their lessons, free-swim slots, staff role, and attendance in one move — no orphaned old names.
Each person's full picture on their account. Open an account and you see both their lessons and their free-swim shifts — the same way lessons already showed.
4

How everything stays in sync

Edits flow to the cloud and back to every device — safely, without clobbering each other.

You edit (owner)
Change shows instantly, then saves with a safe-write check (compare-and-set). If another device saved first, it reloads the newer copy and tells you — never silently overwrites.
→
Cloud (Supabase)
The roster blob + each instructor's record live here, guarded by Row-Level Security.
→
Everyone refreshes
A background poll (~15s) merges everyone's latest — instructor attendance flows to you, your roster flows to them — while protecting edits you're mid-typing.
No signal? No problem. The last roster is cached on the device so it still opens poolside, and any save made offline retries automatically when you're back online.

What each screen shows

Richer dashboards built from that one shared people + roster data.

Live "right now", coverage alerts, who's-on-what per person, attendance at a glance.
My Day instructor
Today's lessons + attendance progress, your free-swim duty & station, your requests.
Day / Rosters
Class-by-class lists, take attendance, add/move swimmers, print & export.
Free Swim
Lifeguard rotation board — who's on duty & where, auto or manual placement.
Today / Staff
Daily staff check-in, no-show → find a replacement, role management (admin only).
Shifts
Every class this week & who teaches it — instructors tap to propose trades.
Accounts admin
Create / rename / disable / delete logins; see each person's lessons + shifts.
Requests
Owner approves/declines trades; applies the change to the week instantly.

System status

What's live and working, what you adjust day-to-day, and what's worth a glance.

✓ Live & working

  • Owner-only account create / delete
  • Attendance + free-swim rotation

  • Rosters, classes, the active day/week

⚠ Keep an eye on

  • Clean any duplicate accounts (old retries)
  • Keep the Edge Function's "Verify JWT" OFF
  • Deploy = drag the zip, wait for "Published"
  • Review new dashboards on a phone
